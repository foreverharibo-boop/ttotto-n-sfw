# 또또(N)SFW · 0.2.0

또또SFW **0.2.42**와 또또NSFW **0.13.26**의 기능·설정·수집 형식을 보존한 통합 확장입니다. 표시 이름은 또또(N)SFW이며, 기존 통합판의 저장 키는 유지합니다.

## 설치

1. 기존 두 확장을 삭제하지 말고, 확장 관리에서 **비활성화**합니다.
2. SillyTavern의 확장 설치에서 아래 저장소 주소를 입력합니다.

   `https://github.com/foreverharibo-boop/ttotto-n-sfw`

3. 새로고침한 뒤 통합판을 활성화합니다. 마법봉 메뉴의 **또또(N)SFW**로 엽니다.
4. 최초 사용 시 기존 전역 설정과 현재 채팅 설정을 통합판 전용 공간으로 복사합니다. 다른 채팅도 열 때 복사하며, 메시지 기록은 읽을 때 해당 메시지의 모든 저장 스와이프를 복사합니다. 원본 두 확장의 기록은 변경하지 않습니다.

기존 두 확장의 실행 코드가 아직 로드되어 있으면 통합판은 실행을 보류하고 비활성화·새로고침을 안내합니다. 두 버전을 동시에 돌리지 않기 위한 처리입니다. 확장 업데이트는 이 저장소에서 받습니다.

## 0.2.0 단일 장면 엔진

- `core.js` 하나가 담당 모드, 생성 중 상태, 보고서 수집/저장, 다음 요청 주입을 관리합니다. SFW/NSFW는 별도 엔진이 아니라 모드별 기능 모듈입니다.
- 개별 생성 인터셉터와 엔진 간 브릿지를 배포 코드에서 제거했습니다. 과거 SFW 인계 대기/복귀 플래그는 담당 판정에 사용하지 않습니다.
- 보고서를 모두 읽은 뒤 한 번에 태그를 정리하고, 하나의 메시지 저장소 `ttottoUnifiedScene`에 보관합니다. 기존 통합판/단독판의 모든 저장 스와이프는 읽을 때 복사하며 원본은 남깁니다. 설정 키도 유지합니다.
- NSFW 모드에서는 해당 탭에 전체 수집 정보를 표시하고, 일반 모드에서는 일반 탭에 표시합니다. 수집한 사물·시간·환경·인물·대화 정보와 현재 모드의 진행 지시를 한 주입문으로 만듭니다.
- 유효한 수동 수정과 현재 담당 모드의 위치/자세를 우선하여 같은 요청에 상충하는 장소나 자세를 넣지 않습니다. 원래 AI 보고서 값은 별도로 보존합니다.
- 생성 중인 보고서는 수집하지 않으며, 스와이프/재생성에서는 담당만 유지하고 이전 본문 정보를 복사하지 않습니다. 채팅 전환은 생성 상태와 보정 대기를 함께 초기화합니다.
- 선택적 종료 브릿지는 단일 코어 안의 한 번짜리 마무리 단계입니다. 다른 엔진에 응답이나 해제 신호를 기다리지 않으며, 수신 이벤트 없이 생성 종료만 오는 경우에도 대기에 갇히지 않습니다.
- 기존 제어·보조 분석·기록 비우기·진단을 유지했습니다. 기능 모듈은 자체 이벤트를 구독하거나 외부 주입 슬롯에 쓰지 않습니다.
- 검증: 배포 코어/기능 모듈 대상 통합·구조·시작 검사 31개와 원본 기능 호환 회귀 검사 278개 통과. 5개 화면 크기 및 실제 입력 조작 검증을 완료했습니다. 범위는 [검수 기록](AUDIT.md)에 구분했습니다.

## 0.1.9 담당 화면·전환 검수

- 현재 담당 탭에만 수집값을 표시합니다. NSFW 개입 중 SFW 수집 영역도 숨기며, 반대 방향과 채팅 미선택 상태에도 같은 규칙을 적용합니다. 설정과 개입 조작은 유지합니다.
- 각 담당 장면의 수집→저장→다음 생성 주입을 확인했습니다. NSFW에서도 공통 사물·인물·시간·환경·대화 기록을 함께 사용합니다. 숨긴 탭 때문에 저장된 공통 기록을 삭제하지 않습니다.
- NSFW 전체 사용을 끄거나 종료 브릿지를 끈 경우, 과거 인계 대기 때문에 SFW까지 대기로 남는 조건을 수정했습니다. 종료 브릿지가 켜진 채팅별 해제는 기존처럼 한 번 마무리 지시를 보낸 뒤 인계합니다.
- 이벤트·감시·생성 인터셉터에서 두 내부 엔진의 주입문을 완성한 뒤 하나의 슬롯에 한 번 등록합니다. 조합 중간에 이전 담당의 지시가 섞인 주입문을 노출하지 않습니다.
- 원본 기능·수집 스키마·설정 대조, 통합 테스트 20개 및 기존 테스트 278개를 통과했습니다. 5개 화면 크기에서 양방향 담당 표시와 실제 엔진의 수집/주입 경로를 확인했습니다. 상세 범위와 한계는 [검수 기록](AUDIT.md)에 적었습니다.

## 0.1.8 친밀 장면 수집 정보·주입 보완

- 친밀 장면에서도 장소·유형·시간·환경·중요 사물·인물 상태를 일반 장면과 같은 입력칸·인물 카드 형태로 표시합니다. 공통 수집값은 읽기 전용이며 기존 친밀 상태 편집 기능은 유지합니다.
- NSFW 개입 중일 때만 수집 영역을 표시합니다. 휴지·감지 대기 중에는 수집값을 숨기고 개입/분석 버튼과 설정은 유지합니다.
- 다음 생성 요청에 공통 사물·외형·자세·소지품·신체 상태를 포함한 장면 사실을 전달합니다. 서사 강도/단계는 관측 정보로 전달하며 친밀 온도/단계와 구분합니다.
- 최근 전개·대사·다음 후보도 해당 기능 설정과 금지/무시 필터에 따라 전달합니다. 친밀 목표 진행 중에는 공통 후보를 억제하며, 일반 장면의 진행 속도·단계 제한을 강제로 적용하지 않습니다.
- 장소/시간/환경/사물/인물 사실은 전환 방지 규칙을 꺼도 유지합니다. 대화 흐름 규칙 및 관련 값은 기존 대화 흐름 설정을 따릅니다.
- 친밀 장면의 주입문 보기에 공통 정보·보고 요청도 함께 표시합니다. 본문·스와이프가 일치하지 않는 최신 기록은 공통 사실/후보로 주입하지 않습니다.
- 검증: 통합 테스트 16개, 기존 SFW 75개·NSFW 203개, 실제 엔진을 불러온 브라우저에서 5개 화면 크기와 수집→저장→표시→프롬프트 생성 경로를 확인했습니다. 실제 모델 응답 품질을 보장하는 테스트는 아닙니다.

## 0.1.7 친밀 장면의 공통 수집 정보 표시

- 친밀 장면 상태 화면에 장소·시간·환경·중요 사물·인물 외형/위치/소지/상태·최근 전개/대화·대화 흐름·장면 유형/강도/진행 단계·다음 전개 후보를 함께 표시합니다.
- 기존 접촉·의복·온도·친밀 진행 단계와 조작 기능도 유지합니다. 공통 보고서의 장면 강도/진행 단계는 친밀 온도/단계로 바꾸지 않습니다.
- 현재 응답의 선택된 스와이프와 본문이 일치하는 기록만 표시합니다. 본문 변경·미수집·채팅 미선택 시 이전 기록을 현재 정보처럼 표시하지 않습니다.
- 저장 형식·수집 로직·설정 배치·로딩 화면 감지 차단은 유지합니다.

## 0.1.6 장면별 화면 복원

- 일반 장면·친밀 장면 탭을 복원했습니다. 각 장면에서 상태와 설정을 바로 선택합니다.
- 각 설정 아래 접이식 문제 해결에 해당 장면의 진단 기능을 배치했습니다. 공통 메뉴의 전환 알림·통합 진단 다운로드도 유지합니다.
- 전환 연속성·대화 흐름 설정은 일반 장면 설정으로 돌아갔으며, 친밀 장면에도 적용되는 동작은 그대로입니다.
- 0.1.5의 APP_READY·실제 채팅 선택 조건과 조용한 첫 진입 처리는 유지합니다. 설정값·수집 기록은 변경하지 않습니다.

## 0.1.5 설정 통합·시작 조건 수정

- 장면 상태·설정 두 화면으로 정리했습니다. 장면 상태에서는 일반/친밀 기록을 선택합니다.
- 설정은 공통 설정, 접이식 일반 장면 설정, 친밀 장면 설정으로 모았습니다. 전환 연속성·대화 흐름은 두 장면에 적용되는 공통 항목이며, 기존 장면별 값과 연결 프로필은 별도로 보존합니다.
- 설정 맨 아래 접이식 문제 해결에 두 진단 패널과 통합 다운로드를 배치했습니다. 기존 조작 요소를 이동해 원래 이벤트와 저장 기능을 유지합니다.
- DOM 준비나 초기화 시작 시점에는 실행하지 않고 Silly의 APP_READY 이후 초기화합니다. 캐릭터/그룹과 채팅 ID가 있는 경우에만 장면 수집·판정·주입을 허용합니다.
- 첫 진입·채팅 전환·채팅 미선택 시 추적 시작 알림을 내지 않습니다. 이후 실제 담당 전환 알림만 선택적으로 표시합니다.

## 0.1.4 화면 정리

- 중복된 전체 상태 탭을 제거하고 일반 장면·친밀 장면 탭만 표시합니다.
- 창을 열면 현재 담당 장면을 표시합니다. 감지 대기·사용 중지 상태에서는 일반 장면을 엽니다. 창을 보는 중에는 탭을 자동으로 바꾸지 않습니다.
- 자동 전환 알림 설정과 양쪽 진단 다운로드는 두 탭에서 접근 가능한 접이식 공통 메뉴로 옮겼습니다.
- 기존 수집·저장·주입 로직과 두 장면의 조작 화면은 유지합니다.

## 0.1.3 화면 수정

- 마법봉 항목을 Silly 기본 목록 형태로 맞추고 버튼 테두리를 제거했습니다.
- 팝업을 화면 중앙에 표시하며, 키보드·화면 회전으로 표시 영역이 바뀌면 크기와 위치를 갱신합니다.
- 제목·닫기·탭을 유지하고 긴 내용은 본문 영역에서 스크롤합니다.
- 본문·배경·테두리·선택 탭·기록 칩은 Silly 테마 색상을 사용합니다.

## 한 창에서 관리

- **일반 장면 / 친밀 장면:** 각 장면의 상태·설정을 바로 선택합니다. 창을 열면 현재 담당 장면이 선택되며, 사용 중에는 자동으로 탭을 바꾸지 않습니다.
- **문제 해결:** 각 장면 설정 맨 아래 접혀 있으며, 해당 진단의 켜기·복사·다운로드·비우기를 제공합니다.
- **공통 메뉴:** 자동 전환 알림 설정과 양쪽 진단 통합 다운로드를 제공합니다.
- 확장 설정 탭에는 패널을 추가하지 않습니다. 마법봉 버튼 하나로만 창을 엽니다. 확장 관리의 설치/활성화 항목은 유지합니다.
- 자동 전환 팝업은 기본적으로 끄고, 창 상단에 현재 담당을 표시합니다. 수동 조작 결과와 오류·슬로우번 경고는 유지합니다.

| 성적 온도·친밀 진행 단계 | 친밀 보고서에 보존; 서사 강도/단계와 혼용하지 않음 |
| 영어/한국어 값 | 원래 이중 언어 형식 유지 |
| 선택 스와이프·본문 서명·수집 시각·수동 보정 대상 | 원래 검증 형식 유지 |

## 통합 동작

외부 이벤트는 하나의 런타임에서 받아 단일 `core.js`로 보냅니다. 담당 판정·생성 상태·수집·저장·주입을 이 코어가 처리하며, 외부에 등록하는 생성 인터셉터·주입 슬롯·답변 감시 타이머도 각각 하나입니다. `modes/`는 기존 파서·설정·화면·슬로우번·반복 방지·보조 분석 등을 제공하는 기능 라이브러리입니다. 별도 수집 루프나 이벤트 구독, 개별 주입, 엔진 간 인계 브릿지는 없습니다.

완성된 답변은 **두 보고서를 먼저 보관하고 나서** 각 태그를 정리합니다. 친밀 장면에서도 일반 보고서를 조건 없이 요청하므로 시간·환경·소지품·몸 상태·대화 흐름이 수집 대상에서 빠지지 않습니다. 일반 보고 요청은 기록용입니다. **대화 흐름 추적·장면 전환 연속성**은 일반 장면 설정의 스위치에 따라 친밀 장면에도 적용합니다. 최신 답변과 서명이 일치하는 기록의 시간·장소·환경, 대화 주제·미응답 질문·새 사실을 주입하며, 사용자가 이미 답한 질문이나 명시적으로 바꾼 화제·시간·장소는 새 맥락을 따릅니다. 본문 수정으로 무효화된 기록은 주입하지 않습니다. 일반 장면의 속도·단계 제한·목표 지시는 이 공통 규칙에 포함하지 않습니다. 두 보고서를 요청할 때에는 각 태그를 하나씩 출력하도록 명시합니다.

단일 확장으로 통합한 것 자체가 추가 보조 AI 호출을 만들지는 않습니다. 자동 보정 설정은 각각 보존하며, 현재 담당 엔진의 기존 조건에 따라 동작합니다. 두 보고서를 모두 요청하는 장면에서는 보고서 출력 토큰이 늘어날 수 있습니다.

본문이 실제로 수정되면 이전 기록을 유효한 것으로 다시 붙이지 않습니다. 온도 자동 모드는 온도가 누락·무효라는 이유만으로 장면 종료로 판단하지 않습니다. 유효한 낮은 온도나 명확한 일상 전환에 대한 기존 해제 규칙은 유지합니다.

## 개발·검증

```sh
python3 scripts/build.py
node --test tests/*.test.mjs
node scripts/test-legacy.mjs
```

- `vendor/`: 기능 비교를 위한 기준 원본과 기존 테스트입니다. 원본 버전·해시는 `provenance.json`에 기록했습니다.
- `scripts/build.py`, `scripts/single_core.py`: 원본의 기능을 보존하고 독립 제어부를 제거하여 `modes/`를 재현합니다. 생성 파일을 직접 고치지 않습니다.
- `runtime.js`: SillyTavern 연결·설정 이관·단일 이벤트 구독·알림을 관리합니다.
- `core.js`: 담당 모드·생성 상태·보고서 수집·중앙 저장소·단일 주입문을 관리합니다.
- `ui.js`: 마법봉 창 하나에 두 모드의 모든 조작 화면을 배치합니다.

0.2.0 검증은 배포 코어/기능 모듈 대상 31개와 기존 기능 호환 빌드의 278개, 총 **309개 통과**입니다. 호환 빌드는 기존 제어부 제거 전의 기능 회귀 검사용이며, 단일 코어의 실제 동작은 통합 검사와 브라우저에서 별도로 검증합니다. 화면의 기존 입력·선택 항목 63개와 전체 수집 필드도 대조했습니다. 0.1.3에서는 Silly 기본 CSS를 적용한 브라우저 검증 화면으로 320·390·768·844·1280px 너비, 밝은/어두운 테마, 긴 내용의 내부 스크롤, 본문 위치 변형 상태에서 팝업 배치를 확인했습니다. 0.1.4에서도 통합·누락 대조 13개와 위 5개 너비의 배치, 담당 장면별 첫 탭, 공통 설정 저장, 양쪽 진단 다운로드를 확인했습니다. 0.1.5에서는 실제 두 엔진을 연결한 검증 화면으로 같은 5개 너비에서 설정 저장·입력 요소 보존·진단 다운로드·홈 화면 대기를 확인했습니다. 0.1.6에서는 같은 5개 너비에서 복원한 장면별 상태·설정 탭, 접이식 진단, 설정 저장·통합 다운로드를 확인하고 시작 조건 검사도 다시 통과했습니다. 실제 모바일 기기에서의 검증은 별도입니다. 실제 SillyTavern 서버·모델 호출·타사 번역 확장 조합도 이 환경에서 검증하지 않았습니다. 원인을 알 수 없는 본문 삭제 자체를 복원하거나 해결했다고 주장하지 않습니다. 모델이 보고서를 누락하거나 필드를 보내지 않는 경우까지 수집을 보장하지 않습니다.

진단 내보내기는 기존과 같이 메모리의 제한된 관찰 기록만 사용합니다. API 키와 대화 본문을 내보내지 않습니다.
