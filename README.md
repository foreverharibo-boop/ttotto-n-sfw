# 또또(N)SFW · 0.1.7

또또SFW **0.2.42**와 또또NSFW **0.13.26**의 기능·설정·수집 형식을 보존한 통합 확장입니다. 표시 이름은 또또(N)SFW이며, 기존 통합판의 저장 키는 유지합니다.

## 설치

1. 기존 두 확장을 삭제하지 말고, 확장 관리에서 **비활성화**합니다.
2. SillyTavern의 확장 설치에서 아래 저장소 주소를 입력합니다.

   `https://github.com/foreverharibo-boop/ttotto-n-sfw`

3. 새로고침한 뒤 통합판을 활성화합니다. 마법봉 메뉴의 **또또(N)SFW**로 엽니다.
4. 최초 사용 시 기존 전역 설정과 현재 채팅 설정을 통합판 전용 공간으로 복사합니다. 다른 채팅도 열 때 복사하며, 메시지 기록은 읽을 때 해당 메시지의 모든 저장 스와이프를 복사합니다. 원본 두 확장의 기록은 변경하지 않습니다.

기존 두 확장의 실행 코드가 아직 로드되어 있으면 통합판은 실행을 보류하고 비활성화·새로고침을 안내합니다. 두 버전을 동시에 돌리지 않기 위한 처리입니다. 확장 업데이트는 이 저장소에서 받습니다.

## 0.1.7 친밀 장면의 공통 수집 정보 표시

- 친밀 장면 상태 화면에 장소·시간·환경·중요 사물·인물 외형/위치/소지/상태·최근 전개/대화·대화 흐름·장면 유형/강도/진행 단계·다음 전개 후보를 함께 표시합니다.
- 기존 접촉·의복·온도·친밀 진행 단계와 조작 기능도 유지합니다. 공통 보고서의 장면 강도/진행 단계는 친밀 온도/단계로 바꾸지 않습니다.
- 현재 응답의 선택된 스와이프와 본문이 일치하는 기록만 표시합니다. 본문 변경·미수집·채팅 미선택 시 이전 기록을 현재 정보처럼 표시하지 않습니다.
- 저장 형식·수집 로직·설정 배치·로딩 화면 감지 차단은 유지합니다.

## 0.1.6 장면별 화면 복원

- 일반 장면·친밀 장면 탭을 복원했습니다. 각 장면에서 상태와 설정을 바로 선택합니다.
- 각 설정 아래 접이식 문제 해결에 해당 장면의 진단 기능을 배치했습니다. 공통 메뉴의 전환 알림·통합 진단 다운로드도 유지합니다.
- 전환 연속성·대화 흐름 설정은 일반 장면 설정으로 돌아갔으며, 친밀 장면에도 적용되는 동작은 그대로입니다.
- 0.1.5의 APP_READY·실제 채팅 선택 조건과 조용한 첫 진입 처리는 유지합니다. 설정값·수집 기록은 변경하지 않습니다.

## 0.1.5 설정 통합·시작 조건 수정

- 장면 상태·설정 두 화면으로 정리했습니다. 장면 상태에서는 일반/친밀 기록을 선택합니다.
- 설정은 공통 설정, 접이식 일반 장면 설정, 친밀 장면 설정으로 모았습니다. 전환 연속성·대화 흐름은 두 장면에 적용되는 공통 항목이며, 기존 장면별 값과 연결 프로필은 별도로 보존합니다.
- 설정 맨 아래 접이식 문제 해결에 두 진단 패널과 통합 다운로드를 배치했습니다. 기존 조작 요소를 이동해 원래 이벤트와 저장 기능을 유지합니다.
- DOM 준비나 초기화 시작 시점에는 실행하지 않고 Silly의 APP_READY 이후 초기화합니다. 캐릭터/그룹과 채팅 ID가 있는 경우에만 장면 수집·판정·주입을 허용합니다.
- 첫 진입·채팅 전환·채팅 미선택 시 추적 시작 알림을 내지 않습니다. 이후 실제 담당 전환 알림만 선택적으로 표시합니다.

## 0.1.4 화면 정리

- 중복된 전체 상태 탭을 제거하고 일반 장면·친밀 장면 탭만 표시합니다.
- 창을 열면 현재 담당 장면을 표시합니다. 감지 대기·사용 중지 상태에서는 일반 장면을 엽니다. 창을 보는 중에는 탭을 자동으로 바꾸지 않습니다.
- 자동 전환 알림 설정과 양쪽 진단 다운로드는 두 탭에서 접근 가능한 접이식 공통 메뉴로 옮겼습니다.
- 기존 수집·저장·주입 로직과 두 장면의 조작 화면은 유지합니다.

## 0.1.3 화면 수정

- 마법봉 항목을 Silly 기본 목록 형태로 맞추고 버튼 테두리를 제거했습니다.
- 팝업을 화면 중앙에 표시하며, 키보드·화면 회전으로 표시 영역이 바뀌면 크기와 위치를 갱신합니다.
- 제목·닫기·탭을 유지하고 긴 내용은 본문 영역에서 스크롤합니다.
- 본문·배경·테두리·선택 탭·기록 칩은 Silly 테마 색상을 사용합니다.

## 한 창에서 관리

- **일반 장면 / 친밀 장면:** 각 장면의 상태·설정을 바로 선택합니다. 창을 열면 현재 담당 장면이 선택되며, 사용 중에는 자동으로 탭을 바꾸지 않습니다.
- **문제 해결:** 각 장면 설정 맨 아래 접혀 있으며, 해당 진단의 켜기·복사·다운로드·비우기를 제공합니다.
- **공통 메뉴:** 자동 전환 알림 설정과 양쪽 진단 통합 다운로드를 제공합니다.
- 확장 설정 탭에는 패널을 추가하지 않습니다. 마법봉 버튼 하나로만 창을 엽니다. 확장 관리의 설치/활성화 항목은 유지합니다.
- 자동 전환 팝업은 기본적으로 끄고, 창 상단에 현재 담당을 표시합니다. 수동 조작 결과와 오류·슬로우번 경고는 유지합니다.

## 통합 동작

하나의 런타임이 이벤트를 받아 친밀 장면의 담당 판정을 먼저 처리합니다. 외부에 등록하는 생성 인터셉터·주입 슬롯·최신 답변 감시 타이머는 각각 하나입니다. 기존의 두 세부 엔진은 기능 손실을 피하기 위해 내부 모듈로 보존했습니다.

완성된 답변은 **두 보고서를 먼저 보관하고 나서** 각 태그를 정리합니다. 친밀 장면에서도 일반 보고서를 조건 없이 요청하므로 시간·환경·소지품·몸 상태·대화 흐름이 수집 대상에서 빠지지 않습니다. 일반 보고 요청은 기록용입니다. **대화 흐름 추적·장면 전환 연속성**은 일반 장면 설정의 스위치에 따라 친밀 장면에도 적용합니다. 최신 답변과 서명이 일치하는 기록의 시간·장소·환경, 대화 주제·미응답 질문·새 사실을 주입하며, 사용자가 이미 답한 질문이나 명시적으로 바꾼 화제·시간·장소는 새 맥락을 따릅니다. 본문 수정으로 무효화된 기록은 주입하지 않습니다. 일반 장면의 속도·단계 제한·목표 지시는 이 공통 규칙에 포함하지 않습니다. 두 보고서를 요청할 때에는 각 태그를 하나씩 출력하도록 명시합니다.

단일 확장으로 통합한 것 자체가 추가 보조 AI 호출을 만들지는 않습니다. 자동 보정 설정은 각각 보존하며, 현재 담당 엔진의 기존 조건에 따라 동작합니다. 두 보고서를 모두 요청하는 장면에서는 보고서 출력 토큰이 늘어날 수 있습니다.

본문이 실제로 수정되면 이전 기록을 유효한 것으로 다시 붙이지 않습니다. 온도 자동 모드는 온도가 누락·무효라는 이유만으로 장면 종료로 판단하지 않습니다. 유효한 낮은 온도나 명확한 일상 전환에 대한 기존 해제 규칙은 유지합니다.

## 개발·검증

```sh
python3 scripts/build.py
node --test tests/*.test.mjs
node scripts/test-legacy.mjs
```

- `vendor/`: 기능 비교를 위한 기준 원본과 기존 테스트입니다. 원본 버전·해시는 `provenance.json`에 기록했습니다.
- `scripts/build.py`: 원본에 통합 어댑터를 적용해 `engines/`를 재현합니다. 엔진 파일을 직접 고치지 않습니다.
- `runtime.js`: 설정/기록 복사, 이벤트 순서, 보고서 선보관, 단일 주입, 알림을 관리합니다.
- `ui.js`: 마법봉 창 하나에 두 엔진의 모든 조작 화면을 배치합니다.

자동 검증은 기존 278개 동작 테스트와 통합·누락 대조·시작 조건 테스트 15개, 총 **293개 통과**입니다. 화면의 기존 입력·선택 항목 63개와 전체 수집 필드도 대조했습니다. 0.1.3에서는 Silly 기본 CSS를 적용한 브라우저 검증 화면으로 320·390·768·844·1280px 너비, 밝은/어두운 테마, 긴 내용의 내부 스크롤, 본문 위치 변형 상태에서 팝업 배치를 확인했습니다. 0.1.4에서도 통합·누락 대조 13개와 위 5개 너비의 배치, 담당 장면별 첫 탭, 공통 설정 저장, 양쪽 진단 다운로드를 확인했습니다. 0.1.5에서는 실제 두 엔진을 연결한 검증 화면으로 같은 5개 너비에서 설정 저장·입력 요소 보존·진단 다운로드·홈 화면 대기를 확인했습니다. 0.1.6에서는 같은 5개 너비에서 복원한 장면별 상태·설정 탭, 접이식 진단, 설정 저장·통합 다운로드를 확인하고 시작 조건 검사도 다시 통과했습니다. 실제 모바일 기기에서의 검증은 별도입니다. 실제 SillyTavern 서버·모델 호출·타사 번역 확장 조합도 이 환경에서 검증하지 않았습니다. 원인을 알 수 없는 본문 삭제 자체를 복원하거나 해결했다고 주장하지 않습니다. 모델이 보고서를 누락하거나 필드를 보내지 않는 경우까지 수집을 보장하지 않습니다.

진단 내보내기는 기존과 같이 메모리의 제한된 관찰 기록만 사용합니다. API 키와 대화 본문을 내보내지 않습니다.
